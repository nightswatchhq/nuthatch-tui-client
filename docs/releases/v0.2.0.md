nuthatch-tui-client 0.2.0 is the first release since 0.1.0 and the first with binaries. It reads
unhealthy nests instead of discarding them, reaches nests on other hosts over ssh, understands
runtimes that mount several nests, and asks a nest for rather less on every refresh. It is still a
read-only client: nothing here writes to a nest.

## Upgrading

There is nothing to migrate. A few things on screen have moved, so a practised eye may look for
them in the old place:

- The data panel's decoded-rows line, which repeated the performance panel, now shows the hot
  store's row count (#14).
- The per-minute decoded-row rate is gone, so the widest performance line fits 100 columns (#4).
- Counters past a million are shortened (`912.3M`), and heights and counts carry digit grouping
  (#4).
- The header and footer take one row each instead of three, so the feed appears from 25 rows and
  every metric line stays whole down to 22 (#11).

## A stalled nest is now visible as one

**0.1.0 treated the 503 a stalled nest answers on `/ready` as a failure and threw it away,** so the
`ATTENTION` state it existed to show could never appear for a stall (#4). The body is now read.
The header carries `(partial)` when an endpoint behind a panel fails, `STALE` when `/ready` itself
stops answering, and restarts are counted, from lifetime counters going backwards, with the time
since the last one. Backfill progress is read from `/ready`, where Nuthatch has published it since
3.4; 0.1.0 read gauges that had been gone since. SQL queries refused and the alert outbox depth
are on screen (#11), `kill` no longer leaves the terminal in raw mode, and `NO_COLOR` is honoured
(#4).

## Less asked of the nest, and a keyboard that answers

`/tables`, `/nest` and `/queries` are fetched once rather than every two seconds (#4). On the
17-table USDC demo that took a refresh from 38 KB to 18 KB. The poll interval follows the nest's
own, held between 2 and 30 seconds, so a five-minute cursor is no longer asked 150 times per
update. Requests run on a thread of their own (#5): against a nest holding each SQL query for two
seconds, 0.1.0 had still not quit two minutes after thirty keypresses, and 0.2.0 quits in 0.05 s.

## Nests on other hosts, and runtimes with several

`--ssh HOST` opens the forward itself, reports a refused key before the dashboard opens, and
reopens a forward that dies with a backoff that doubles to 30 s (#8). Nests can be named in
`~/.config/nuthatch-tui/nests.toml` and opened with `--nest`, or chosen from a list when none is
named (#10). Pointed at a runtime's root, the client finds the roster and steps through the mounted
nests with `n` (#9).

## A list you can find things in

The table list scrolls, pages and filters with `/` (#5, #7), and groups tables under their alias
with state calls together (#13). The feed is laid out from the schema, in declared column order,
and a state call's `result` is shown as the number it encodes. Declared decimals in `nests.toml`
show token amounts whole: on `graph-allocations-nest`, `4.07e19` reads `40.7288` (#12). The sync
gauge measures lag against a poll's worth of blocks, where `1 - lag / tip` read full for any lag an
arbitrum nest could have (#6).

## What it still does not do

- Token decimals are not discovered. Nuthatch does not serve them, and a guessed scale would be a
  wrong number shown with confidence, so undeclared columns stay in base units.
- A restart is seen only while the client is watching, and only if the counters have not climbed
  past their old values by the next sample.
- On a Nuthatch before 3.0.0 hosted off Linux, CPU reads a flat `0.0%` rather than `unavailable`.
- Binaries are built for Apple Silicon macOS and x86_64 Linux with glibc 2.35 or newer. Intel Macs
  and Windows build from source.

## Install

Each tarball has a `.sha256` and a build-provenance attestation. The README has the steps, and
`gh attestation verify` is the one that says this repository built it.
